## 1. 문서 목적 및 개요

본 문서는 할일 관리 웹 애플리케이션 "my-todolist"의 핵심 도메인 개념, 용어, 엔티티, 비즈니스 규칙을 정의한다. 개발팀과 이해관계자 간 공통 언어(Ubiquitous Language)를 확립하여 요구사항 해석의 불일치를 방지하는 것을 목적으로 한다.

엔티티(EN), 비즈니스 규칙(BR), 유스케이스(UC)에는 고유 ID를 부여하여 상호 참조 및 추적이 가능하도록 한다.

## 2. 문제 정의 및 배경

- 인증된 사용자별로 개인화된 할일을 관리할 수 있는 서비스가 부재하다.
- 기존 할일 관리 기능만으로는 일정 계획 수립이 어려워, 할일에 시작일자와 종료일자를 지정하고 이를 기준으로 진행 상태를 추적할 수 있는 기능이 필요하다.

## 3. 용어 정의 (Ubiquitous Language)

| 용어 | 정의 |
|---|---|
| 사용자 (User) | 회원가입 및 로그인을 통해 인증된 후 본 서비스를 이용하는 주체. |
| 카테고리 (Category) | 할일을 분류하는 단위. 사용자가 직접 생성하며, 미지정 시 '기본' 카테고리로 분류된다. |
| 할일 (Todo) | 사용자가 등록하는 작업 항목. 제목, 시작일자, 종료일자, 완료 여부 등의 속성을 가진다. |
| 상태 (Status) | 할일의 진행 상태를 나타내는 값으로, 시작일자·종료일자·완료 여부로부터 파생되어 계산된다. 값은 시작전, 진행중, 완료, 기한초과 중 하나이다. |
| 기본 카테고리 (Default Category) | 사용자가 카테고리를 지정하지 않고 할일을 등록할 때 자동 적용되는 카테고리. |

## 4. 핵심 도메인 엔티티 및 속성

### 4.1 EN-01 User (사용자)

| 속성 | 설명 | 제약조건 |
|---|---|---|
| id | 사용자 식별자 | 시스템 발급, 고유값 |
| email | 로그인 계정 | 고유값, 필수, 형식 검증(이메일 포맷), 중복 가입 불가 |
| password | 인증 정보 | 필수, 최소 8자 이상, 저장 시 해시 처리(평문 저장 금지) |
| name | 사용자 이름/닉네임 | 필수, 1자 이상, 중복 허용, 수정 가능(BR-07 참조) |
| createdAt | 가입일시 | 시스템 자동 기록 |

### 4.2 EN-02 Category (카테고리)

| 속성 | 설명 | 제약조건 |
|---|---|---|
| id | 카테고리 식별자 | 시스템 발급, 고유값 |
| userId | 소유 사용자 | 필수, User 참조 |
| name | 카테고리명 | 필수, 사용자별 유일(대소문자 구분 없이 비교, 앞뒤 공백 제거 후 비교) |
| isDefault | 기본 카테고리 여부 | 사용자당 정확히 1개 존재, 삭제 불가(BR-04 참조) |

카테고리 삭제 시, 해당 카테고리에 속한 Todo는 모두 기본 카테고리로 자동 이관된다(BR-09 참조).

### 4.3 EN-03 Todo (할일)

| 속성 | 설명 | 제약조건 |
|---|---|---|
| id | 할일 식별자 | 시스템 발급, 고유값 |
| userId | 소유 사용자 | 필수, User 참조 |
| categoryId | 소속 카테고리 | 필수, 미지정 시 기본 카테고리로 자동 설정(BR-03 참조) |
| title | 할일 제목 | 필수, 1자 이상 |
| startDate | 시작일자 | 필수, 캘린더 입력 |
| endDate | 종료일자 | 필수, 캘린더 입력, startDate 이상이어야 함(BR-05 참조) |
| isDone | 완료 여부 | 기본값 false, 사용자가 직접 변경 |
| status | 상태 (파생값) | 저장 항목이 아닌 계산값. 4.4 상태 판정 규칙(BR-06) 참조 |

### 4.4 상태(Status) 판정 규칙

Todo의 상태는 저장되는 속성이 아니라 조회 시점의 오늘 날짜, startDate, endDate, isDone 값을 기준으로 계산되는 파생값이다(BR-06).

1. isDone = true → **완료**
2. isDone = false 이고 오늘 < startDate → **시작전**
3. isDone = false 이고 startDate ≤ 오늘 ≤ endDate → **진행중**
4. isDone = false 이고 오늘 > endDate → **기한초과**

## 5. 엔티티 간 관계

- User(EN-01) 1 : N Category(EN-02) — 한 사용자는 여러 카테고리를 가진다.
- User(EN-01) 1 : N Todo(EN-03) — 한 사용자는 여러 할일을 가진다.
- Category(EN-02) 1 : N Todo(EN-03) — 한 카테고리는 여러 할일을 가진다.
- 모든 Category와 Todo는 정확히 하나의 User에 종속된다 (다른 사용자와 공유되지 않음).

## 6. 핵심 비즈니스 규칙

| ID | 규칙 |
|---|---|
| BR-01 | 회원가입 및 로그인 인증을 완료한 사용자만 서비스를 이용할 수 있다. |
| BR-02 | 모든 할일과 카테고리의 CRUD는 소유 사용자 본인만 수행할 수 있다. |
| BR-03 | 할일 등록 시 카테고리를 지정하지 않으면 '기본' 카테고리가 자동 적용된다. |
| BR-04 | 사용자별로 '기본' 카테고리는 가입 시 자동 생성되며 삭제할 수 없다. |
| BR-05 | 할일의 종료일자(endDate)는 시작일자(startDate)보다 앞설 수 없다(endDate ≥ startDate). 위반 시 등록/수정을 거부한다. |
| BR-06 | 할일의 상태(시작전/진행중/완료/기한초과)는 저장값이 아닌 조회 시점 기준의 계산값이다. 판정 기준은 4.4절을 따른다. |
| BR-07 | 사용자는 자신의 계정 정보(이름 등)를 수정할 수 있다. 단, email은 로그인 식별자이므로 수정 범위에서 제외한다. |
| BR-08 | 각 엔티티 생성 시 필수값/형식/중복 제약 위반이 있으면 등록을 거부하고 사유를 반환한다. 예: 회원가입 시 email 중복 또는 비밀번호 형식 미달(EN-01), 카테고리 생성 시 카테고리명 중복(EN-02, 동일 사용자 내). |
| BR-09 | 카테고리 삭제 시 해당 카테고리에 속한 할일은 모두 기본 카테고리로 자동 이관된다. |

## 7. 주요 유스케이스

### UC-01 회원가입 / 로그인 (인증)
- 관련 엔티티/규칙: EN-01, BR-01, BR-08
- 수용 기준:
  - Given 미가입 상태에서, When 유효한 email·password로 회원가입하면, Then 사용자 계정과 기본 카테고리(EN-02, isDefault=true)가 생성된다.
  - Given 이미 등록된 email로, When 회원가입을 시도하면, Then 등록이 거부된다(BR-08).
  - Given 가입된 계정으로, When 올바른 email·password로 로그인하면, Then 인증되어 서비스 이용이 가능해진다.

### UC-02 사용자 정보 수정
- 관련 엔티티/규칙: EN-01, BR-07
- 수용 기준:
  - Given 로그인 상태에서, When name을 변경하면, Then 변경된 name이 저장된다.
  - Given 로그인하지 않은 상태에서, When 정보 수정을 시도하면, Then 거부된다(BR-01).

### UC-03 할일 등록
- 관련 엔티티/규칙: EN-03, BR-03, BR-05
- 수용 기준:
  - Given 로그인 상태에서, When 카테고리 미지정으로 할일을 등록하면, Then 기본 카테고리가 자동 적용된다(BR-03).
  - Given startDate와 endDate를 캘린더로 선택할 때, When endDate < startDate로 입력하면, Then 등록이 거부된다(BR-05).

### UC-04 할일 목록 조회 및 필터링
- 관련 엔티티/규칙: EN-03, BR-06
- 수용 기준:
  - Given 할일 목록에서, When 카테고리를 선택해 필터링하면, Then 해당 카테고리의 할일만 표시된다.
  - Given 할일 목록에서, When 상태 필터(시작전/진행중/완료/기한초과)를 선택하면, Then 4.4절 판정 규칙에 따라 계산된 상태와 일치하는 할일만 표시된다.

### UC-05 할일 수정 (편집화면)
- 관련 엔티티/규칙: EN-03, BR-02, BR-05
- 수용 기준:
  - Given 본인 소유 할일에 대해, When 편집화면에서 속성을 변경하고 저장하면, Then 변경 내용이 반영된다.
  - Given 타 사용자 소유 할일에 대해, When 수정을 시도하면, Then 거부된다(BR-02).

### UC-06 할일 삭제
- 관련 엔티티/규칙: EN-03, BR-02
- 수용 기준:
  - Given 본인 소유 할일에 대해, When 삭제를 요청하면, Then 목록에서 제거된다.
  - Given 타 사용자 소유 할일에 대해, When 삭제를 시도하면, Then 거부된다(BR-02).

## 8. 범위 외 (Out of Scope)

- 할일/카테고리의 다른 사용자와의 공유 및 협업 기능
- 알림(이메일, 푸시 등) 기능
- 첨부파일 업로드
- 할일 우선순위, 반복 일정, 하위 작업(subtask) 관리
- 소셜 로그인 등 인증 방식 확장
