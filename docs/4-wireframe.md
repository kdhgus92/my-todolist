## 1. 문서 개요

### 1.1 목적

본 문서는 할일 관리 웹 애플리케이션 "my-todolist"의 화면 구조를 정의한다. 도메인 개념, 엔티티, 비즈니스 규칙, 유스케이스는 [1-domain-definition.md](./1-domain-definition.md)(v0.3)에, 제품 범위와 기능 요구사항은 [2-prd.md](./2-prd.md)(v0.2)에, 사용자 행동 흐름은 [3-user-scenario.md](./3-user-scenario.md)(v0.1)에 이미 정의되어 있으므로 본 문서는 이를 재서술하지 않고 UC-xx/BR-xx ID로 참조하며, 그 위에 화면 단위의 레이아웃과 UI 요소를 ASCII 와이어프레임으로 구체화한다.

별도의 디자인 툴이나 이미지 산출물 없이, 이 마크다운 문서 자체를 화면 구조 정의의 최종 산출물로 사용한다.

### 1.2 관련 문서

- 도메인 정의서: [docs/1-domain-definition.md](./1-domain-definition.md) — 엔티티(EN-xx), 비즈니스 규칙(BR-xx), 유스케이스(UC-xx) 정의
- PRD: [docs/2-prd.md](./2-prd.md) — 제품 범위, 기능/비기능 요구사항, 기술 아키텍처
- 사용자 시나리오: [docs/3-user-scenario.md](./3-user-scenario.md) — 사용자 행동 흐름

### 1.3 레이아웃 기준

- 데스크톱 웹을 기준 레이아웃으로 작성한다(PRD 5.2절).
- 모바일 반응형은 핵심 화면인 할일 목록 화면 1개만 별도로 간단히 제시한다. 나머지 화면은 폼/리스트 폭이 줄어드는 정도의 자연스러운 반응형 재배치를 전제하며 별도 도식은 생략한다(1인 2일 개발 규모, 과설계 지양).
- 접근성(a11y)은 본 프로젝트 범위 외이므로 와이어프레임에 별도 반영하지 않는다(PRD 3.2, 5.5절).

## 2. 화면 목록

| 화면 ID | 화면명 | 관련 UC | 인증 필요 여부 |

| SC-01 | 회원가입 | UC-01 | 불필요 |

## 3. 공통 UI 컴포넌트

### 3.1 공통 헤더/네비게이션 (인증 후 전 화면 공통)

```
+--------------------------------------------------------------------+
| my-todolist        [ 할일 목록 ]  [ 마이페이지 ]        [로그아웃] |
+--------------------------------------------------------------------+
```

- 좌측: 서비스 로고/이름 (클릭 시 할일 목록으로 이동)
- 중앙: 주요 화면 이동 탭 — 할일 목록(SC-03), 마이페이지(SC-05)
- 우측: 로그아웃 버튼 — 클릭 시 access_token/refresh_token 폐기 후 SC-02(로그인)로 이동
- 비인증 상태(SC-01, SC-02)에서는 이 헤더를 노출하지 않는다(BR-01).

### 3.2 공통 확인(Confirm) 다이얼로그

삭제 계열 액션(할일 삭제 UC-06, 카테고리 삭제)에서 공통으로 사용한다.

```
        +----------------------------------+
        |  정말 삭제하시겠습니까?           |
        |  이 작업은 되돌릴 수 없습니다.    |
        |                                  |
        |            [ 취소 ]  [ 삭제 ]    |
        +----------------------------------+
```

### 3.3 공통 폼 검증 메시지 영역

회원가입/로그인/할일 등록·수정/카테고리 생성 폼 공통으로, 입력 필드 하단에 인라인 오류 메시지를 노출한다(BR-05, BR-08 위반 시).

```
[ 종료일자 입력 ]
⚠ 종료일자는 시작일자보다 빠를 수 없습니다.
```

## 4. 화면별 와이어프레임

### 4.1 SC-01 회원가입

- 관련 UC/BR: UC-01, BR-08(중복 email·비밀번호 형식 위반 시 거부)

```
+--------------------------------------------------------------------+
|                          my-todolist                               |
|                                                                      |
|                     +--------------------------+                   |
|                     |        회원가입          |                   |
|                     +--------------------------+                   |
|                     | 이메일                   |                   |
|                     | [______________________] |                   |
|                     |                           |                   |
|                     | 비밀번호 (8자 이상)       |                   |
|                     | [______________________] |                   |
|                     |                           |                   |
|                     | 이름                      |                   |
|                     | [______________________] |                   |
|                     |                           |                   |
|                     | ⚠ 이미 사용 중인 이메일입니다. (조건부 노출) |
|                     |                           |                   |
|                     |     [   가입하기   ]      |                   |
|                     |                           |                   |
|                     | 이미 계정이 있으신가요? [로그인]              |
|                     +--------------------------+                   |
+--------------------------------------------------------------------+
```

- 주요 요소: 이메일, 비밀번호, 이름 입력 필드 / 가입하기 버튼 / 로그인 화면(SC-02) 이동 링크
- 인터랙션: 가입하기 클릭 시 클라이언트 1차 검증(이메일 형식, 비밀번호 길이) 후 서버 요청. 서버에서 email 중복 또는 형식 미달 시 인라인 오류 표시(BR-08). 성공 시 SC-02(로그인)로 이동(가입과 동시에 기본 카테고리가 내부적으로 생성되나 화면상 별도 안내는 하지 않음).

### 4.2 SC-02 로그인

- 관련 UC/BR: UC-01, BR-01

```
+--------------------------------------------------------------------+
|                          my-todolist                               |
|                                                                      |
|                     +--------------------------+                   |
|                     |         로그인            |                   |
|                     +--------------------------+                   |
|                     | 이메일                   |                   |
|                     | [______________________] |                   |
|                     |                           |                   |
|                     | 비밀번호                  |                   |
|                     | [______________________] |                   |
|                     |                           |                   |
|                     | ⚠ 이메일 또는 비밀번호가 올바르지 않습니다.   |
|                     |                           |                   |
|                     |     [   로그인   ]        |                   |
|                     |                           |                   |
|                     | 계정이 없으신가요? [회원가입]                 |
|                     +--------------------------+                   |
+--------------------------------------------------------------------+
```

- 주요 요소: 이메일/비밀번호 입력 필드, 로그인 버튼, 회원가입(SC-01) 이동 링크
- 인터랙션: 로그인 성공 시 access_token/refresh_token 발급 후 SC-03(할일 목록)으로 이동. 실패 시 인라인 오류 메시지 노출, 인증 없이는 SC-03~SC-06에 접근할 수 없다(BR-01).

### 4.3 SC-03 할일 목록 (필터 포함)

- 관련 UC/BR: UC-04, BR-02(본인 소유만 조회), BR-06(상태는 조회 시점 계산값)

```
+--------------------------------------------------------------------+
| my-todolist        [ 할일 목록 ]  [ 마이페이지 ]        [로그아웃] |
+--------------------------------------------------------------------+
| 카테고리: [ 전체 v ]   상태: [ 전체 v ]        [+ 카테고리 관리]    |
|          (전체/기본/과제/아르바이트...)  (전체/시작전/진행중/완료/기한초과) |
+--------------------------------------------------------------------+
|                                                    [ + 할일 등록 ]  |
+--------------------------------------------------------------------+
| [ ] 알고리즘 과제 제출        과제     2026-08-20~2026-08-27  기한초과 |
| [ ] 팀플 회의 준비            과제     2026-08-25~2026-08-30  진행중   |
| [x] 아르바이트 스케줄 확정    아르바이트 2026-08-10~2026-08-15  완료   |
| [ ] 여름 특강 신청            기본     2026-09-01~2026-09-05  시작전   |
|                                                                      |
|  (각 행 클릭 시 SC-04 수정 폼으로 이동, 우측 끝에 [수정] [삭제] 아이콘 노출) |
|                                                                      |
|                     (조건에 맞는 항목이 없을 경우)                  |
|                     "표시할 할일이 없습니다."                       |
+--------------------------------------------------------------------+
```

- 주요 요소:
  - 카테고리 필터 드롭다운(전체 + 사용자 카테고리 목록, 기본 카테고리 포함)
  - 상태 필터 드롭다운(전체/시작전/진행중/완료/기한초과) — 4.4절 판정 규칙에 따라 계산된 값 기준
  - 할일 등록 버튼 → SC-04(등록 모드)
  - 카테고리 관리 버튼 → SC-06 모달 오픈
  - 할일 목록 테이블/리스트: 완료 체크박스(isDone 즉시 토글), 제목, 카테고리, 기간(startDate~endDate), 상태 배지, 행별 수정/삭제 액션
- 인터랙션:
  - 카테고리 필터 변경 시 해당 카테고리의 할일만 표시(UC-04)
  - 상태 필터 변경 시 오늘 날짜 기준 계산된 상태와 일치하는 항목만 표시(BR-06)
  - 완료 체크박스 클릭 시 즉시 isDone 토글 및 상태 배지 재계산(UC-05 연계)
  - 행의 삭제 아이콘 클릭 시 3.2절 확인 다이얼로그 → 확정 시 삭제(UC-06, BR-02)
  - 본인 소유 할일만 조회되며 타 사용자 데이터는 노출되지 않는다(BR-02)
- 상태 배지 표기 예: `시작전`(회색) / `진행중`(파랑) / `완료`(초록, 취소선) / `기한초과`(빨강)

### 4.4 SC-04 할일 등록 / 수정 폼

- 관련 UC/BR: UC-03(등록), UC-05(수정), UC-06(삭제 진입점), BR-03, BR-05

```
+--------------------------------------------------------------------+
| my-todolist        [ 할일 목록 ]  [ 마이페이지 ]        [로그아웃] |
+--------------------------------------------------------------------+
|  < 목록으로                                                          |
|                                                                      |
|                 +--------------------------------+                 |
|                 |   할일 등록 / 할일 수정         |                 |
|                 +--------------------------------+                 |
|                 | 제목                            |                 |
|                 | [____________________________] |                 |
|                 |                                  |                 |
|                 | 시작일자          종료일자       |                 |
|                 | [ 📅 2026-08-25 ] [ 📅 2026-08-30 ] |             |
|                 | ⚠ 종료일자는 시작일자보다 빠를 수 없습니다.       |
|                 |                                  |                 |
|                 | 카테고리                        |                 |
|                 | [ 과제            v ]            |                 |
|                 |   (미선택 시 '기본' 자동 적용)   |                 |
|                 |                                  |                 |
|                 | 완료 여부   [ ] 완료로 표시       | (수정 모드만 노출) |
|                 |                                  |                 |
|                 |  [ 삭제 ]      [ 취소 ]  [ 저장 ] | (삭제=수정 모드만)|
|                 +--------------------------------+                 |
+--------------------------------------------------------------------+
```

- 주요 요소: 제목 입력, 시작/종료일자 캘린더 입력, 카테고리 선택(SC-06에서 만든 카테고리 목록 + 기본), 완료 여부 체크박스(수정 모드에서만 노출), 저장/취소/삭제 버튼
- 인터랙션:
  - 등록 모드: 카테고리 미선택 시 기본 카테고리 자동 적용(BR-03), 완료 여부 필드는 노출하지 않음(신규 등록 시 항상 false)
  - 수정 모드: 진입 시 기존 값이 모두 채워진 상태로 표시, 완료 여부 토글 가능, 삭제 버튼 노출(클릭 시 3.2절 확인 다이얼로그 → 확정 시 삭제 후 SC-03으로 이동, UC-06)
  - 저장 시 종료일자 < 시작일자이면 클라이언트/서버 양쪽에서 거부하고 인라인 오류 표시(BR-05)
  - 저장/삭제 성공 시 SC-03으로 이동하며 목록에 즉시 반영
  - 타 사용자 소유 할일에 URL로 직접 접근 시 조회/저장이 거부된다(BR-02)

```
+--------------------------------------------------------------------+
| my-todolist        [ 할일 목록 ]  [ 마이페이지 ]        [로그아웃] |
+--------------------------------------------------------------------+
|                                                                      |
|                 +--------------------------------+                 |
|                 |          마이페이지             |                 |
|                 +--------------------------------+                 |
|                 | 이메일                          |                 |
|                 | jiwoo@example.com  (수정 불가)  |                 |
|                 |                                  |                 |
|                 | 이름                             |                 |
|                 | [ 김지우_______________________] |                 |
|                 |                                  |                 |
|                 |               [ 저장 ]           |                 |
|                 |                                  |                 |
|                 | ✔ 변경 사항이 저장되었습니다.  (조건부 노출)        |
|                 +--------------------------------+                 |
+--------------------------------------------------------------------+
```

- 주요 요소: email 읽기 전용 표시, name 수정 입력 필드, 저장 버튼, 저장 성공/실패 안내 메시지
- 인터랙션: 저장 클릭 시 변경된 name만 서버에 반영(BR-07). email 필드는 입력 불가(비활성 상태)로 렌더링하여 수정 시도 자체를 차단.

### 4.6 SC-06 카테고리 관리 (모달)

- 관련 UC/BR: UC-03/UC-04 전제 기능, BR-04(기본 카테고리 삭제 불가), BR-08(카테고리명 중복 거부), BR-09(삭제 시 할일 기본 카테고리로 이관)

```
                +----------------------------------------------+
                |  카테고리 관리                          [ x ] |
                +----------------------------------------------+
                |  새 카테고리 이름                             |
                |  [__________________________]  [ 추가 ]      |
                |  ⚠ 이미 존재하는 카테고리명입니다. (조건부)    |
                |                                                |
                |  기본                              [삭제 비활성]|
                |  과제                              [ 삭제 ]    |
                |  아르바이트                        [ 삭제 ]    |
                |                                                |
                |                              [ 닫기 ]          |
                +----------------------------------------------+
```

- 주요 요소: 카테고리 생성 입력 필드 + 추가 버튼, 카테고리 목록(이름 + 삭제 버튼), 기본 카테고리는 삭제 버튼 비활성화
- 인터랙션:
  - 추가 시 동일 사용자 내 이름 중복(대소문자 무시, 앞뒤 공백 제거 비교)이면 등록 거부 및 인라인 오류 표시(BR-08, EN-02)
  - 기본 카테고리는 삭제 버튼이 비활성 처리되어 클릭 자체가 불가하며, 우회 시도 시 서버에서도 거부(BR-04)
  - 일반 카테고리 삭제 클릭 시 3.2절 확인 다이얼로그 → 확정 시 삭제되고, 해당 카테고리에 속한 할일은 모두 기본 카테고리로 자동 이관(BR-09). 모달을 닫으면 SC-03 목록/필터가 최신 카테고리 목록으로 갱신된다.

## 5. 모바일 반응형 레이아웃 (SC-03 할일 목록)

데스크톱 기준 SC-03을 모바일 폭(약 375~480px)에서 재배치한 예시. 필터는 세로로 쌓이고, 목록은 테이블形이 아닌 카드형으로 전환한다.

```
+---------------------------+
| my-todolist        [ ☰ ] |
+---------------------------+
| 카테고리: [ 전체      v ] |
| 상태:     [ 전체      v ] |
| [ + 카테고리 관리 ]        |
| [ + 할일 등록 ]            |
+---------------------------+
```

- 헤더의 [할일 목록]/[마이페이지]/[로그아웃] 메뉴는 햄버거(☰) 아이콘 안으로 축소된다.
- 그 외 화면(SC-01, 02, 04, 05, 06)은 원래 폭이 좁은 단일 컬럼 폼 구조이므로 데스크톱 와이어프레임의 중앙 카드 영역이 화면 폭에 맞춰 자연스럽게 줄어드는 것으로 충분하며 별도 도식은 생략한다.

## 6. 화면 흐름

```
[SC-01 회원가입] --가입 성공--> [SC-02 로그인]
[SC-02 로그인] --인증 성공--> [SC-03 할일 목록]
[SC-01] <--"로그인" 링크--- [SC-02] --"회원가입" 링크--> [SC-01]

[SC-03 할일 목록]
   ├─ [+ 할일 등록] ---------------> [SC-04 등록 모드] --저장--> [SC-03]
   ├─ 행 클릭 / [수정] -------------> [SC-04 수정 모드] --저장/삭제--> [SC-03]
   ├─ [+ 카테고리 관리] ------------> [SC-06 카테고리 관리(모달)] --닫기--> [SC-03]
   ├─ 헤더 [마이페이지] ------------> [SC-05 마이페이지] --헤더 이동--> [SC-03]
   └─ 헤더 [로그아웃] --------------> [SC-02 로그인]

세션(access_token) 만료 시: 자동으로 refresh_token 기반 재발급을 시도하고,
실패하면 임의 화면에서 [SC-02 로그인]으로 강제 이동한다(PRD 6.3절).
```

- SC-03(할일 목록)이 인증 후 진입하는 허브 화면이며, 등록/수정(SC-04)·카테고리 관리(SC-06)·마이페이지(SC-05)는 모두 SC-03을 경유해 접근하거나 SC-03으로 복귀한다.
- 비인증 상태에서 SC-03~SC-06에 접근 시도 시 SC-02(로그인)로 리다이렉트된다(BR-01).
